# Problems

Problems seen in operation or found by the checks (cold room, boiler starting at the wrong time, unsafe value
on the board). Append-only; process in [`process.md`](process.md) §8, checked by `tools/sh_process_check.py`.

- **ID:** `PB-n`, next free number, never reused.
- **Requirements:** the requirement IDs the problem breaks (active IDs, cited in full), or `—`.
- **Board commit:** what the board reported (`sh_process_check.py board`) when the problem was seen.
- **Safety:** `yes` if it touches a requirement of the AGENTS.md §3 safety list. An open safety problem blocks
  a release.
- **Missed by:** the test (`SWE.5-TCxx.y`) that should have caught it, `no test`, or the check that found it.
- **Checker:** text of the checker ERROR line(s) this problem explains, each in backticks, without line numbers.
  While the row is `open`, `analysing` or `rejected`, a matching ERROR is reported as `KNOWN (PB-n)` and does not
  fail the run (CI fails only on new errors). After `fixed` / `closed` a matching ERROR is a regression. `—` if none.
- **Status:** `open` → `analysing` → `fixed` (Fix = commit) → `closed` (fix confirmed on the board),
  or `rejected` (not a problem or accepted as is, say why in Cause).
- The fixing commit cites the ID in its message, e.g. `fix(control): keep valve open during overrun (PB-3)`.
